2. Pipelines YAML

Le gestionnaire charge tous les YAML sous pipeline/ (rglob). Les noms d objets restent uniques entre sim_v1, sim_v2 et ml.

  • sim_v2 : source ventes → scenarios → dataset pivot → restitution → LOO
  • sim_v1 : features hotel → reference pairs → R1–R4 → LOO
  • ml : vue v_ml_training_dataset pour CatBoost

3. sim_v1 (regles ROD Excel)

Chaine R1 clients → R2 mix ±10 % → R3 categories → R4 surface → marge produit. LOO : exclusion de l hotel des pairs de sa solution. Perimetre : 6 hotels (H5586 exclu).

python run.py sim-v1 --rebuild
# → data/files/output/sim_v1/eval_sim_v1_loo.xlsx

4. sim_v2 (restitution coefficients)

Coefficients unitaires par variable de mix et solution. Methodes A (moyenne toutes variables) et B (moyenne par famille). LOO : exclusion de toutes les simulations de l hotel.

python run.py sim-v2 --rebuild
# → data/files/output/sim_v2/eval_sim_v2_loo.xlsx

5. CatBoost

Multi-cibles (CA, marge marche, marge coef). Leave-one-hotel-out. Hyperparametres : depth 6, lr 0.05, iterations 800, L2 6, early stopping 60.

python run.py ml --rebuild
# → data/files/output/ml/eval_catboost_loo.xlsx
# → models/catboost/*.cbm

7. Interface web

  • /eval — comparaison visuelle des LOO
  • /predict — formulaire hotel (champs modifiables) + boutons sim_v1 / sim_v2 / CatBoost
  • /hotels — liste pilotes et acces prediction
  • User / Configuration — mix type & gammes : si on monte ou baisse une part, l’écart est réparti proportionnellement aux parts actuelles des autres (pas à parts égales). Items verrouillés exclus. Voir doc/FEATURE_MIX_REDISTRIBUTION.md.
  • User / Optimisation — assortiment optimal (top produits par m_lin / marge) puis CA ; mix reco pré-chargés et ré-éditables. Voir doc/FEATURE_OPTIMAL_MIX.md.

7.bis Mix — redistribution proportionnelle

Exemple : A=50 %, B=30 %, C=20 %. Si A passe à 60 %, on retire 10 % de B+C au prorata 30:20 → B=24 %, C=16 %. Si A passe à 40 %, on rend 10 % au même prorata → B=36 %, C=24 %.

Code : MixPanel.setValue (UI), vary_one (optimisation grid).
