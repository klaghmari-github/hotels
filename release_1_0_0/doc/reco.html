1. Règles Excel (ordre strict)

La feuille REGLES POUR RECO DU CONCEPT définit un filtre en cascade. La première condition vraie fixe le concept affiché en premier. Les 3 P&L restent calculables ; la reco n’est pas exclusive.

RègleCellule / libellé ExcelConditionRésultat
#1 B4 · D4–E4 / K4 Nb. de chambres entre 0 et 49 SIMPLY
#2 B15 · D15–D16 · K16 = YES ≥ 1 catégorie parmi
Cosmetics · Kids items · Ready-to-wear · Accessories · Souvenirs		 LIBERTY
#3 B27 · D27–D28 · K28 mètres linéaires > 4 LIBERTY
#4 B42 · D42 · K42 = YES Hôtel déjà en possession d’une vitrine réfrigérée LIBERTY

Sinon B36 (critères résiduels) ≥ 50 ch. · aucune des 5 cat. · m_lin ≤ 4 · pas de vitrine · TO ≥ 70 % CONNECTED
Note G20 Excel : « Le choix doit être possible pour les hôtels NOV et MER » — LIBERTY doit rester accessible pour Novotel / Mercure même si le panel catégories est pauvre (avertissement métier, pas un hard-block dans la release).

2. Arbre de décision (pseudo-code)

SI nb_chambres ≤ 49 → SIMPLY SINON SI ≥1 cat. ∈ {Cosmetics, Kids, RTW, Accessories, Souvenirs} → LIBERTY SINON SI mètres_linéaires > 4 → LIBERTY SINON SI possède_vitrine_réfrigérée → LIBERTY SINON SI TO_moyen < 0,70 → LIBERTY SINON → CONNECTED
Point critique Excel : la recommandation n’est pas le max de CA brut. On peut recommander la 2e meilleure solution en CA si les règles structurelles (taille, catégories, ML, vitrine, TO) l’imposent.

3. Lab éditable — attributs hôtel → décision

Tous les attributs qui entrent dans l’arbre sont éditables. Le chemin pris est surligné ; la solution recommandée s’affiche en direct.

Autres catégories (SOS, Hygiene…) influencent le CA (R3 sim_v1) mais pas cet arbre de reco.

    4. Recommandation dans l’app release (complément ROI)

    Une fois les simulations lancées (sim_v1 / sim_v2 / ml), src/user/business.py → recommend() choisit parmi les résultats chiffrés :

    // Filtre léger taille (écho règle #1) SI nb_chambres < 50 ET une prédiction SIMPLY existe : candidats = { SIMPLY seulement } warning = "Hotel < 50 chambres — SIMPLY privilégié" // Choix final recommandé = argmax ROI_annuel parmi candidats // ROI_annuel = marge_nette_annual = (marge_ventes − coûts) × 12
    Deux couches :
    1. Arbre Excel (cette page) → concept « affiché en premier » / adéquation opérationnelle.
    2. Reco ROI app → parmi les P&L calculés, meilleur ROI annuel (avec filtre taille < 50 ch. → SIMPLY).

    Voir aussi roi.html pour le détail marge − coûts.
