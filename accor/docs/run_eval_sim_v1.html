Evaluation du simulateur ROD v1

Documentation de la methode leave-one-out, des regles appliquees, des indicateurs et de l'interface graphique

Objet Lancement Sources de donnees Indicateurs Leave-one-out Regles ROD v1 Interface Fichier Excel Metriques Fichiers code Limites

1. Objet

Ce document decrit le module d'evaluation du simulateur ROD version 1 (regles Excel). L'evaluation mesure la capacite du moteur de regles a predire le chiffre d'affaires HT mensuel et la marge produit mensuelle d'un hotel pilote lorsque cet hotel n'entre pas dans la construction de la reference.

L'evaluation ne remplace pas les applications admin et user. Elle s'appuie sur le meme moteur de revenus (regles R1 a R4) et produit un classeur Excel ainsi qu'une interface de consultation.

Point d'entree interface : python run_eval_sim_v1.py (port 5057 par defaut). Resultats stocks : data/eval_sim_v1_loo.xlsx.

2. Lancement et cycle de vie

2.1 Generer les resultats

python run_eval_sim_v1.py --rebuild

Cette commande recalcule l'ensemble du leave-one-out, reecrit le fichier Excel, puis s'arrete. Les resultats sont considers stables tant que les donnees de ventes, les fiches hotels ou le mapping pilotes ne changent pas.

2.2 Consulter l'interface

python run_eval_sim_v1.py
# puis ouvrir http://127.0.0.1:5057/

L'interface lit uniquement le fichier Excel deja calcule. Elle n'execute pas de nouveau le leave-one-out a chaque ouverture de page.

Le facteur 30,5 est le nombre de jours moyen par mois retenu dans les regles ROD (identique au moteur user / Excel).

5. Methode leave-one-out

Pour chaque hotel pilote H appartenant a une solution S :

  1. On retire H de la liste des hotels de la solution S.
  2. On construit une reference (baseline) en moyenne simple des indicateurs des hotels restants de S (les pairs).
  3. On applique le moteur de regles v1 sur les parametres de H, en utilisant cette reference a la place des pivots multi-hotels habituels.
  4. On compare le CA HT predit et la marge produit predite aux valeurs reelles mensuelles de H (moyennes calculees a l'etape data).

Exemple SIMPLY : pour evaluer H2075, la reference est construite avec HB6A3 uniquement. Pour evaluer HB6A3, la reference est H2075.

Si une solution ne contenait qu'un seul hotel apres exclusion, le code se rabat sur les autres pilotes toutes solutions confondues, puis sur les pivots Excel internes en dernier recours.

5.1 Contenu de la reference (pairs)

Moyenne des pairs sur les champs suivants :

  • ca_fb_mensuel, ca_nf_mensuel
  • nb_ventes_mensuel
  • clients_mois
  • mix_fb
  • m_lin
  • nb_chambres, taux_occupation, guests_per_chambre

Grandeurs derivees pour la lecture metier :

  • taux_conversion_ref = nb_ventes_ref / clients_ref
  • panier_moyen_ref = (ca_fb_ref + ca_nf_ref) / nb_ventes_ref
  • ca_10_fb = ca_fb_ref / 10 et ca_10_nfb = ca_nf_ref / 10 (sensibilite mix R2)
  • ca_1ml_fb = ca_fb_ref / m_lin_ref et ca_1ml_nfb = ca_nf_ref / m_lin_ref (sensibilite surface R4)

6. Regles du simulateur v1 appliquees a la prediction

Le calcul de prediction utilise le module RevenueRules (meme logique que le parcours user / Excel). Les besoins clients (categories produit) sont tous actives pour l'evaluation afin de neutraliser le levier R3 entre hotels.

6.1 Entrees hotel evalue

  • nb_chambres, taux_occupation, guests_per_chambre
  • clients_mois = n x TO x guests x 30,5
  • m_lin (metres lineaires)
  • mix_fb (et mix_nf = 1 - mix_fb)

6.2 Regle R1 - clients acheteurs

taux_acheteur = nb_ventes_ref / clients_ref
nb_acheteurs  = clients_hotel x taux_acheteur
CA_F&B        = (ca_fb_ref / nb_ventes_ref) x nb_acheteurs
CA_N-F&B      = (ca_nf_ref / nb_ventes_ref) x nb_acheteurs

Interpretation : on reprend le taux de conversion et le panier par vente de la reference, appliques au volume de clients heberges de l'hotel evalue.

6.3 Regle R2 - impact du mix

steps = (mix_fb_hotel - mix_fb_ref) x 10
CA_F&B  = CA_F&B  + ca_10_fb  x steps
CA_N-F&B = CA_N-F&B + ca_10_nfb x (-steps)

Un ecart de 10 points de mix F&B (0,10) correspond a un pas de 1. L'ajustement redistribue le CA entre F&B et N-F&B selon les sensibilites ca_10_fb et ca_10_nfb issues de la reference.

6.4 Regle R3 - categories produit

Chaque categorie F&B ou N-F&B active ajoute un coefficient, chaque categorie inactive en retire un. Le multiplicateur final est : 

mult = 1 + somme(+coeff si ON, -coeff si OFF)
CA_canal = CA_canal x mult

Dans l'evaluation, toutes les categories sont forcees a ON. Le multiplicateur est donc le meme pour tous les hotels evalues (effet constant, comparable d'un hotel a l'autre).

6.5 Regle R4 - surface ou equipements

  • SIMPLY et LIBERTY : ajustement selon l'ecart de metres lineaires (m_lin_hotel - m_lin_ref), avec sensibilites ca_1ml_fb et ca_1ml_nfb.
  • CONNECTED : ajustement selon le nombre de frigos froid par rapport a la reference d'equipement (logique Excel Connected).

6.6 Marge produit predite

marge = (CA_F&B - CA_F&B / coef_F&B) + (CA_N-F&B - CA_N-F&B / coef_N-F&B)

Coefficients utilises (alignes simulateur) : coef_F&B = 2,6 ; coef_N-F&B = 1,45.

La marge predite est donc une marge produit regle Excel, distincte de la colonne montant_marge issue des ventes brutes (qui peut provenir d'un autre mode de calcul historique).

7. Interface graphique (onglets)

L'interface presente une barre d'onglets. Chaque onglet correspond a une feuille du classeur Excel ou a une vue de synthese.

7.1 Onglet data

Tableau d'une ligne par hotel pilote. Colonnes : identite, solution, parametres d'exploitation, clients, mix, CA, ventes, taux de conversion, panier moyen, CA par client, marge, nombre de mois.

Obtention : lecture de la feuille data du fichier eval_sim_v1_loo.xlsx, elle-meme produite par build_data_table lors du rebuild.

7.2 Onglets eval_Hxxxx

Un onglet par hotel pilote (ex. eval_H2075, eval_H0373). Contenu :

  • Cartes resume : CA reel, CA predit, erreur absolue CA, erreur absolue marge
  • Parametres hotel et reference (chambres, TO, clients, m_lin, mix, conversions, paniers)
  • Tableau detail des regles : pour chaque variable, l'etape (Hotel evalue, Reference pairs, R1, R2, R3, R4, Sortie, Controle), la valeur et la source

Obtention : pour l'hotel H, leave-one-out sur sa solution, appel a RevenueRules.compute avec les overrides de reference, puis export des entrees et sorties dans la feuille eval_Hxxxx.

7.3 Onglet eval

Vue de synthese de toutes les evaluations individuelles :

  • Indicateurs globaux : MAE CA, MAE marge, MAPE CA, nombre d'hotels
  • MAE par solution (SIMPLY, LIBERTY, CONNECTED)
  • Tableau detail : pour chaque hotel, pairs utilises, CA reel / predit, erreurs, marges, nombre de mois

Obtention : agregation des resultats leave-one-out (feuille eval du classeur).

8. Structure du fichier Excel

Fichier : data/eval_sim_v1_loo.xlsx

9. Metriques d'evaluation

9.1 Erreur absolue par hotel

err_ca(H)    = |CA_pred(H) - CA_reel(H)|
err_marge(H) = |marge_pred(H) - marge_reel(H)|

9.2 MAE (Mean Absolute Error)

MAE_CA    = moyenne_sur_H( err_ca(H) )
MAE_marge = moyenne_sur_H( err_marge(H) )

La MAE est aussi calculee par solution (moyenne restreinte aux hotels de SIMPLY, LIBERTY ou CONNECTED).

9.3 MAPE CA

MAPE_CA = moyenne_sur_H( 100 x err_ca(H) / |CA_reel(H)| )
          pour les hotels dont |CA_reel| est non nul

Unite : pour cent. La MAPE complete la MAE lorsque les niveaux de CA different fortement d'un hotel a l'autre.

9.4 Interpretation

  • Une MAE CA elevee indique que le moteur de regles, alimente par les seuls pairs de la meme solution, s'ecarte en moyenne du CA mensuel observe.
  • L'erreur de marge compare une marge regle Excel a une marge historique ventes : un ecart structurel peut exister si les definitions ne sont pas identiques.
  • Avec peu d'hotels par solution (2 ou 3), le leave-one-out est sensible a l'heterogeneite de taille (chambres, TO, mix) entre pairs.

11. Limites et points d'attention

  • L'evaluation porte uniquement sur les hotels pilotes listes dans rod_pilot_concepts.json (hotels disposant de ventes).
  • La reference leave-one-out repose sur un tres petit nombre de pairs (souvent un seul hotel pour SIMPLY et LIBERTY).
  • Les besoins clients R3 sont tous actives : l'evaluation ne mesure pas la qualite du profiling categories, seulement le coeur R1, R2, R4 et l'effet de taille / mix.
  • Les couts, la marge nette et l'amortissement ne sont pas evalues dans ce module v1 (seuls CA HT et marge produit).
  • Le fichier Excel doit etre regeneres (--rebuild) apres toute modification des ventes, des fiches hotels ou du mapping pilotes.

12. Resume du flux

1. Charger pilotes, hotel_data, ventes, simulateur_data
2. Calculer les indicateurs mensuels de chaque hotel (feuille data)
3. Pour chaque hotel H de solution S :
     a. pairs = hotels de S sans H
     b. reference = moyenne des indicateurs des pairs
     c. predire CA et marge de H via R1 - R2 - R3 - R4
     d. calculer |pred - reel|
     e. ecrire la feuille eval_Hxxxx
4. Agreger les erreurs (feuille eval) : MAE, MAPE, MAE par solution
5. L'interface lit le classeur et affiche data / eval_Hxxxx / eval
