## 3. Performance IA vs simulateur ROD (constat 2026-07-02)

### Consigne utilisateur
> L'IA n'est **toujours pas** mieux que le simulateur brut. Trouver un plan pour améliorer la qualité.

### Réponse — diagnostic (`performance_report.json`, 5 hôtels, 4 mois 2026)

| Métrique | ROD | IA |
|----------|-----|-----|
| Écart moyen absolu période | **69,7 %** | **49,9 %** |
| IA meilleure | — | **2 / 5** hôtels |

L'IA est **légèrement** meilleure en moyenne absolue, mais **instable** hôtel par hôtel (Nice : ROD surestime ; Megève : ROD surestime fortement ; Tour Eiffel : les deux dérivent).

**Causes racines identifiées** :

1. **n=6 hôtels train** — XGBoost multi-output sur ~200 features / 24 targets : sur-apprentissage + variance élevée.
2. **Features POI/météo peu exploitées** — enrichissement pas fusionné systématiquement dans `X_descriptive.csv` au init.
3. **Targets trop granulaires** — modèle entraîné sur `t_m{mm}_ca_total` mais pipeline IA reconstruit via % TYPE/GAMME : décalage train ↔ inférence.
4. **Pas de feature géo-contextuelle métier** — ex. distance plage pour maillots (non codée avant cette session).
5. **Mix produits** — UI avec cases à cocher « exclure » au lieu de sliders % alignés ventes F&B / NON-F&B + GAMME.

## 5. Catégories & sous-catégories (ventes)

### Consigne utilisateur
> Les catégories c'est juste **F&B** ou **NON-F&B**. Les sous-catégories sont les **GAMME** du fichier Excel/CSV ventes — **ne pas les inventer**.
> Ce n'est pas cocher/décocher : c'est un **slider** 0–100 %. 0 % = exclu, 100 % = on ne vend que ça (reste à 0).
> Toujours afficher la **somme restante à distribuer** + bouton **distribuer équitablement** sur les sous-catégories à % non nul.

### Réponse / implémentation

**Source ventes** (`001.queryVentes.csv`) :
- `TYPE` : `F&B`, `NON-F&B`
- `GAMME` : `ACCESSOIRES`, `ALCOOL`, `COSMETIQUE`, `FOOD SALEE`, `FOOD SUCREE`, `JEUX / ENFANTS`, `PAP`, `SANS ALCOOL`, `SOS`, `SOUVENIRS`

**API** : `GET /api/sales-catalog` → arbre TYPE → GAMME.

**UI** (onglet Contraintes) :
- Slider F&B / NON-F&B (somme 100 %)
- Sous chaque TYPE : sliders GAMME issues du catalogue
- Bandeau « Reste à distribuer : X % »
- Bouton « Distribuer équitablement »

**Payload simulation** :
```json
{
  "store": {
    "mix": {
      "fb_share": 0.7,
      "non_fb_share": 0.3,
      "subcategory_shares": {
        "F&B::ALCOOL": 0.15,
        "F&B::SANS ALCOOL": 0.85
      }
    }
  }
}
```
